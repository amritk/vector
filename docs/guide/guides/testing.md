# Testing an implementation

A checked contract implies a test: its vectors, and its properties at
samples z3 chose on the domain's boundaries. `vector spec emit` writes that
test, and `vector spec run` emits it and runs it: a Nish test against a nish
checkout, and a test in [another language](#other-languages) by its own
tooling. This page uses the RFC 5869 contract and nish's own
`std/crypto/hkdf.ts`; [From a spec to a contract](spec-to-contract.md)
covers how the contract is made.

## Emit the test

`spec emit <contract.json> -o <file>` checks the contract and writes its
test. It does not make directories, so make the one the test goes in first:

```sh
mkdir -p test/spec
./dist/vector spec emit contracts/rfc5869-hkdf-sha256.json -o test/spec/hkdf.ts
```

```text
wrote test/spec/hkdf.ts
```

The test is generated, never edited. Its header says how to regenerate it and
pins the SHA-256 of the contract it came from, which [`spec
stale`](pr-gates.md#stale) compares:

```sh
head -9 test/spec/hkdf.ts
```

```text
// GENERATED by vector from the contract "rfc5869-hkdf-sha256" (RFC 5869,
// HMAC-based Extract-and-Expand Key Derivation Function (HKDF)). Do not edit: change the contract and regenerate with
//   vector spec emit contracts/rfc5869-hkdf-sha256.json -o test/spec/hkdf.ts.
//
// Each check names its clause in brackets and the requirements it covers in
// parentheses; every requirement's text is quoted above its checks.
// Property samples were chosen by the solver (boundaries) and a seeded PRNG.
//
// vector-contract-sha256: fbe3c7c0bc77655517141ba694439510d12bb75f863e56e3197d86223e3786cf
```

`-o` is required:

<!-- exit 2 -->
```sh
./dist/vector spec emit contracts/rfc5869-hkdf-sha256.json
```

```text
vector: spec emit: -o <file> is required
```

A contract that does not check is refused (exit 1) and nothing is written.
`emit` accepts `--spec`, `--nish-root`, `--nish` and `--format` but reads none
of them: the sources are found from the contract, and nothing is compiled.

## Test your own modules

A contract whose module is not a `nish/` one is about a module of your own
project. `--package <name>=<dir>` says where such modules live: the module
`<name>/<path>` is the file `<dir>/<path>.ts`, and the test imports it by its
path relative to the directory the test is written in. Give it once for each
package; when two names match a module, the longer one wins. vector tests
itself this way. Its own spec `specs/vector-core-hex.md` names the module
`vector/core/hex`, which is `src/core/hex.ts`:

```sh
mkdir -p tests/dogfood
./dist/vector spec emit contracts/vector-core-hex.json --package vector=src -o tests/dogfood/vector-core-hex_test.ts
```

```text
wrote tests/dogfood/vector-core-hex_test.ts
```

```sh
sed -n 3p tests/dogfood/vector-core-hex_test.ts
sed -n 12p tests/dogfood/vector-core-hex_test.ts
```

```text
//   vector spec emit contracts/vector-core-hex.json --package vector=src -o tests/dogfood/vector-core-hex_test.ts.
import { sha256Hex, toHex } from "../../src/core/hex";
```

Without `--package`, such a module is refused, and nothing is written:

<!-- exit 1 -->
```sh
./dist/vector spec emit contracts/vector-core-hex.json -o /tmp/hex_test.ts
```

```text
vector: contracts/vector-core-hex.json: vector/core/hex is not a nish/ module: give --package <name>=<dir> to say where your own modules live
```

A flag that is not `<name>=<dir>`, a name of `nish`, or a name given twice
is bad usage (exit 2), and so is a package that places a module at a file
that does not exist:

<!-- exit 2 -->
```sh
./dist/vector spec emit contracts/vector-core-hex.json --package vector=lib -o /tmp/hex_test.ts
```

```text
vector: vector/core/hex: --package places it at lib/core/hex.ts, which does not exist
```

`spec run` takes the same flag. It writes the test to `-o`, or else to a fresh
temporary directory, before it emits it, so the imports are relative to where
the test runs. A test kept with `-o` has the same regenerate line `spec emit`
writes.

vector's own tests of itself live in `tests/dogfood/`, and `npm test` runs
them. `npm run dogfood` checks that each one is what vector makes of its spec
now: it extracts the spec's XML again and compares the contract, checks the
contract with `--run-sources` and `--module`, runs `spec stale`, and reruns
the test's regenerate command. A test that changes is left regenerated and
reported, so a change to the emitter shows up in a diff of the tests it
writes.

## Other languages

A contract is not tied to Nish: the same checks run against a port of the
module in another language. `--lang <id>` picks the language the test is
written in, and `--harness <h>` the framework that runs it:

| Language | `--lang` | Harnesses | Runs with |
| --- | --- | --- | --- |
| Nish | `nish` (the default) | `standalone` | the nish root (see [Run it](#run-it)) |
| Python | `python` | `standalone` (the default), `pytest` | `VECTOR_PYTHON`, else `python3` |
| Rust | `rust` | `standalone` (the default), `cargo` | `VECTOR_RUSTC`, else `rustc` |
| Go | `go` | `standalone` (the default), `gotest` | `VECTOR_GO`, else `go` |
| TypeScript | `typescript` | `standalone` (the default), `node` | `VECTOR_NODE`, else `node` |

The other languages vector has a naming table for (`ruby`, `zig`, `cpp`,
`csharp`, `c`, `java`, `kotlin`, `php`, `swift` and `dart`) have no emitter yet, and `--lang` says so (exit 2):

<!-- exit 2 -->
```sh
./dist/vector spec emit contracts/vector-core-hex.json --lang zig -o hex_test.zig
```

```text
vector: spec emit: --lang zig: vector has no emitter for zig yet (it has: nish, python, rust, go, typescript)
```

A function is called by its name in the language, from the contract's
language table: a contract's `toHex` is Python's `to_hex`, unless the contract
names it for Python itself. A name the language cannot use, such as a
keyword, or two functions that would share one name, is refused (exit 1).

`--package <name>=<dir>` places modules the same way, with the language's
extension: `vector/core/hex` is `<dir>/core/hex.py`, loaded by its path
relative to the test. A `nish/` module has no Python file of its own, so a
Python port of one is mapped like any package. `tests/fixtures/python/`
holds the ports vector checks its Python tests against:

```sh
./dist/vector spec run contracts/vector-core-hex.json --lang python --package vector=tests/fixtures/python/vector
```

```text
SATISFIED: vector-core-hex (exit 0)
  pass  R-HEX-LEN
  pass  R-HEX-DIGITS
  pass  R-SHA256
```

A Python test needs no nish root. vector runs it with `python3 -B`, so it
writes no bytecode beside your modules; set `VECTOR_PYTHON` to run it with
another interpreter. The verdict, the transcript and its `vector-done` line
are the same as a Nish test's, and so are its failures:

<!-- exit 1 -->
```sh
./dist/vector spec run contracts/vector-core-hex.json --lang python --package vector=tests/fixtures/python/broken/vector
```

```text
VIOLATED: vector-core-hex (exit 1)
  fail  R-HEX-LEN
  fail  R-HEX-DIGITS
  pass  R-SHA256
FAIL  [V2] every nibble boundary, high nibble first, lowercase (R-HEX-LEN, R-HEX-DIGITS)
      expected "000f10ff", got "000F10FF"
…
```

Every test is a standalone program, which is how `spec run` runs it. With
`--harness pytest` the file also holds a `test_<clause>` function for each
clause, so pytest collects it with the rest of your suite, and a failing
clause fails with the same detail the transcript prints:

<!-- illustrative -->
```sh
./dist/vector spec emit contracts/vector-core-hex.json --lang python --harness pytest --package vector=src/py -o tests/test_hex.py
pytest tests/test_hex.py
```

The regenerate line in the test's header keeps `--lang` and `--harness`
when they are not the defaults. A harness the language has not is bad usage:

<!-- exit 2 -->
```sh
./dist/vector spec run contracts/vector-core-hex.json --lang python --harness junit
```

```text
vector: spec run: --harness junit: python tests run standalone or pytest
```

### Rust

A Rust test is one file that needs the standard library alone. Each function
is called by its Rust name (`to_hex`), from the module's crate path
(`use nish::crypto::hkdf::{…}`), or, for a module `--package` places, from
the `.rs` file there, loaded with `#[path]` relative to the test. A bytes
input is passed as `&[u8]` and a string as `&str`; an optional input is an
`Option<&[u8]>` or `Option<&str>`. A result may come back as any type that
derefs to bytes or a string, so `Vec<u8>`, `[u8; 32]`, `String` and `&str`
all check; an optional result is an `Option` of one. `tests/fixtures/rust/`
holds the ports vector checks its Rust tests against:

```sh
./dist/vector spec run contracts/vector-core-hex.json --lang rust --package vector=tests/fixtures/rust/vector
```

```text
SATISFIED: vector-core-hex (exit 0)
  pass  R-HEX-LEN
  pass  R-HEX-DIGITS
  pass  R-SHA256
```

`spec run` compiles the test with `rustc --edition 2021 -C
overflow-checks=on` in a temporary directory, then runs it; set
`VECTOR_RUSTC` to build with another compiler. The contract's `+`, `-` and
`*` wrap, so an implementation that overflows where the contract wraps
panics, and that check fails with the panic's message (`panicked: attempt to
add with overflow`). A test that does not compile prints no transcript, so
its verdict is ERROR, with rustc's messages.

With `--harness cargo` the file also holds a `#[test] fn test_<clause>` for
each clause, so `cargo test` (or `rustc --test`) runs the same checks, and a
failing clause panics with the detail the transcript prints. A property
with no samples is `#[ignore]`d:

```sh
./dist/vector spec run contracts/rfc5869-hkdf-sha256.json --lang rust --harness cargo --package nish=tests/fixtures/rust/nish
```

```text
SATISFIED: rfc5869-hkdf-sha256 (exit 0)
  pass  R-EXTRACT
  pass  R-SALT
  pass  R-PRK-LEN
  pass  R-L
  pass  R-INFO-EMPTY
  pass  R-OKM-LEN
  pass  R-OKM-FIRST
  pass  R-T
```

### Go

A Go test is one `package main` file that needs the standard library alone.
Each function is called by its exported Go name (`ToHex`, `HkdfExpandSha256`;
`IDI32` for `idI32`, since ID is an initialism), through its module's import
path: `vector/core/hex` is `import "vector/core/hex"`. A name that is not
exported, such as one a `go` override spells in lower case, is refused
(exit 1). A bytes value is a `[]byte` and a string a `string`; an optional
input is a `*[]byte` or `*string`, nil when absent, and a result that may
refuse is `(T, error)`, any non-nil error being the refusal.
`tests/fixtures/go/` holds the ports vector checks its Go tests against:

```sh
./dist/vector spec run contracts/vector-core-hex.json --lang go --package vector=tests/fixtures/go/vector
```

```text
SATISFIED: vector-core-hex (exit 0)
  pass  R-HEX-LEN
  pass  R-HEX-DIGITS
  pass  R-SHA256
```

`spec run` builds the test with `go build` in a temporary module, offline
and on the local toolchain, then runs it; set `VECTOR_GO` to build with
another `go`. Each `--package <name>=<dir>` becomes a module of its own,
`<name>`, with one package per `.go` file at the file's path: `--package
vector=src/go` puts `src/go/core/hex.go` at `vector/core/hex`. The contract's
`+`, `-` and `*` wrap, as Go's do, and an f64 compares bit for bit unless the
clause gives a tolerance. A check that panics fails with the panic's
message, and a test that does not build prints no transcript, so its verdict
is ERROR, with go's messages.

With `--harness gotest` the file also holds a `func Test_<clause>(*testing.T)`
for each clause, so `go test` runs the same checks when the file is saved as
a `_test.go` file in the package, and a failing clause fails with the detail
the transcript prints. A property with no samples is skipped:

```sh
./dist/vector spec run contracts/rfc5869-hkdf-sha256.json --lang go --harness gotest --package nish=tests/fixtures/go/nish
```

```text
SATISFIED: rfc5869-hkdf-sha256 (exit 0)
  pass  R-EXTRACT
  pass  R-SALT
  pass  R-PRK-LEN
  pass  R-L
  pass  R-INFO-EMPTY
  pass  R-OKM-LEN
  pass  R-OKM-FIRST
  pass  R-T
```

### TypeScript

A TypeScript test is one `.ts` file that Node runs as it is, with its
built-in type stripping: it needs no npm package and no tsc. Each function is
called by its TypeScript name (`toHex`), imported from the module's path, or,
for a module `--package` places, from the `.ts` file there, imported by a
path relative to the test. A bytes value is a `Uint8Array`, an integer up to
32 bits a `number` and an i64 or u64 a `bigint`; a function that refuses
returns `null`, and an absent optional input is passed as `undefined`. A
bytes result may come back as any typed-array view or an `ArrayBuffer`.
`tests/fixtures/typescript/` holds the ports vector checks its TypeScript
tests against:

```sh
./dist/vector spec run contracts/vector-core-hex.json --lang typescript --package vector=tests/fixtures/typescript/vector
```

```text
SATISFIED: vector-core-hex (exit 0)
  pass  R-HEX-LEN
  pass  R-HEX-DIGITS
  pass  R-SHA256
```

`spec run` writes the test to a temporary directory and runs it with `node`;
set `VECTOR_NODE` to run it with another. JavaScript's numbers are binary64,
so the test writes the contract's arithmetic out: `+`, `-` and `*` are exact
in bigint and wrap to their operands' width, `%` truncates and is 0 on a zero
divisor, and string lengths count UTF-8 bytes. A test Node cannot load prints
no transcript, so its verdict is ERROR, with Node's messages.

With `--harness node` the file also holds a `test()` from `node:test` for
each clause, so `node --test` runs the same checks with the rest of your
suite, and a failing clause fails with the detail the transcript prints. A
property with no samples is skipped:

```sh
./dist/vector spec run contracts/rfc5869-hkdf-sha256.json --lang typescript --harness node --package nish=tests/fixtures/typescript/nish
```

```text
SATISFIED: rfc5869-hkdf-sha256 (exit 0)
  pass  R-EXTRACT
  pass  R-SALT
  pass  R-PRK-LEN
  pass  R-L
  pass  R-INFO-EMPTY
  pass  R-OKM-LEN
  pass  R-OKM-FIRST
  pass  R-T
```

## Run it

`spec run <contract.json>` emits the test to a temporary file (or to `-o`),
builds it with nish, runs it and reads what it printed. It needs a nish to
build with, found in this order:

1. `--nish-root <dir>`;
2. the `VECTOR_NISH_ROOT` environment variable;
3. `../nish`, when that is a directory.

With none of them, it stops before building anything:

<!-- exit 2 -->
```sh
./dist/vector spec run contracts/rfc5869-hkdf-sha256.json
```

```text
vector: spec run: ../nish: not a nish checkout (give --nish-root or set VECTOR_NISH_ROOT)
```

The root is either a nish install, with an executable `libexec/nish` (the
`.nish/` that `scripts/fetch-nish.sh` makes is one), or a nish checkout with a
built `build/seed`. vector copies that compiler into a scratch directory with
the root's own `std/` beside it, so the test is built against the root's
standard library, and removes the copy afterwards. The pinned install answers
for the std it ships:

```sh
./dist/vector spec run contracts/rfc5869-hkdf-sha256.json --nish-root .nish
```

```text
SATISFIED: rfc5869-hkdf-sha256 (exit 0)
  pass  R-EXTRACT
  pass  R-SALT
  pass  R-PRK-LEN
  pass  R-L
  pass  R-INFO-EMPTY
  pass  R-OKM-LEN
  pass  R-OKM-FIRST
  pass  R-T
```

The environment variable does the same:

```sh
VECTOR_NISH_ROOT=.nish ./dist/vector spec run contracts/rfc5869-hkdf-sha256.json
```

```text
SATISFIED: rfc5869-hkdf-sha256 (exit 0)
…
```

A directory that is neither is refused:

<!-- exit 2 -->
```sh
./dist/vector spec run contracts/rfc5869-hkdf-sha256.json --nish-root src
```

```text
vector: spec run: /path/to/vector/src is neither a nish install (libexec/nish) nor a checkout with build/seed
```

`--nish <bin>` skips all of this and builds with that compiler as it is, with
whatever std it reads. `--spec` is accepted and not read.

### Slow vectors

An [iterated vector](spec-to-contract.md#an-iterated-vector) marked `slow`,
such as RFC 7748's million X25519 calls, is too long to run on every test
run. Without `--slow`, `spec emit` writes it skipped, with the reason `slow:
pass --slow to run` (Rust's `#[ignore]` and node:test's `skip` carry the same
reason), and `spec run` lists it as skipped, never as passed. A requirement
that only skipped vectors cover is skipped too, and `SATISFIED` is judged over
what ran. Here `CHAIN-100000` hashes 100,000 times and is the only vector
covering `R-LOWER`:

```sh
./dist/vector spec run tests/fixtures/iterate-emit/contracts/sha256-chain.json --package vector=src --nish-root .nish
```

```text
SATISFIED: sha256-chain (exit 0)
  pass  R-CHAIN
  skip  R-LOWER
  skip  CHAIN-100000 (slow; pass --slow)
```

`--slow` runs it, and a Nish test it runs is built with `--profile speed`,
which costs about a second more to compile and runs a long loop some ten
times faster (RFC 7748's 1,000,000 iterations take about 105 seconds):

```sh
./dist/vector spec run tests/fixtures/iterate-emit/contracts/sha256-chain.json --package vector=src --nish-root .nish --slow
```

```text
SATISFIED: sha256-chain (exit 0)
  pass  R-CHAIN
  pass  R-LOWER
```

Only a Nish test is built optimized. A test in another language is built as
its harness always builds it, so a million-step vector can take longer than
`spec run`'s 600-second limit there.

A run whose every vector was skipped as slow is an `ERROR`: nothing ran, and
the text report says so on its own line:

```text
every vector was skipped as slow, so nothing ran: pass --slow
```

In `--json`, each clause skipped as slow also has `"slow": true`.

### Truncated vectors

A [truncated vector](spec-to-contract.md#a-truncated-vector) is checked on
the result's first bytes only: the emitted test of RFC 4231 test case 5
compares the first 16 bytes of `hmacSha256`'s 32 with the printed value. A
result shorter than the truncation fails, in every language, with a detail
like `a 15-byte result, shorter than the 16 bytes it is truncated to`; it is
never compared as it is, so an implementation that returns too little does
not pass by matching the start.

`spec run` names the truncation on each line it prints about the vector, as
`  skip  4.6-256 (first 128 bits) (slow; pass --slow)` or after a failure's
line, and in the JSON report the clause has `"truncate": {"bits": 128}`, as
the contract writes it.

## A planted bug

Copy the install, then let HKDF-Expand accept one octet more than RFC 5869
allows (`L = 255*HashLen + 1`):

```sh
cp -rL .nish ../nish-bug
sed -i '174s/length > HKDF_MAX_BLOCKS \* SHA256_SIZE ||/length > HKDF_MAX_BLOCKS * SHA256_SIZE + 1 ||/' ../nish-bug/std/crypto/hkdf.ts
```

Every vector RFC 5869 prints still passes. The property that pins the output
length does not, at a sample z3 put on the boundary:

<!-- exit 1 -->
```sh
./dist/vector spec run contracts/rfc5869-hkdf-sha256.json --nish-root ../nish-bug
```

```text
VIOLATED: rfc5869-hkdf-sha256 (exit 1)
  pass  R-EXTRACT
  pass  R-SALT
  pass  R-PRK-LEN
  fail  R-L
  pass  R-INFO-EMPTY
  fail  R-OKM-LEN
  pass  R-OKM-FIRST
  pass  R-T
FAIL  [P-EXPAND-LENGTH] Expand gives exactly L octets for L <= 255*HashLen and refuses a longer L (R-L, R-OKM-LEN)
      sample 4 of 40 (len(prk) = 39, len(info) = 31, n = 8161): the assertion is false
```

Bugs planted the same way in the ChaCha20-Poly1305 contract's module are
caught at boundaries too:

| Planted bug | Caught by | At |
| --- | --- | --- |
| HKDF-Expand accepts `L = 255*HashLen + 1` | P-EXPAND-LENGTH | `n = 8161` |
| the AEAD tag compare skips the last byte | P-TAMPER-SEALED | `bit = 127`, empty plaintext |
| the AEAD pads block-aligned AAD with 16 zeros instead of none | P-TAG-IS-POLY1305 | `len(aad) = 0` |

The third passes every vector RFC 8439 prints: only the property, which
rebuilds the MAC input from the other functions, catches it.

## The verdicts

| Verdict | Means | Exit |
| --- | --- | --- |
| `SATISFIED` | the test built, ran, and every clause that ran passed (a [slow vector](#slow-vectors) skipped without `--slow` did not run) | 0 |
| `VIOLATED` | a clause failed; each failure prints with its sample | 1 |
| `ERROR` | the test did not build, ran past its time, or printed a transcript vector cannot trust | 1 |
| refused | the contract does not check, so no test was emitted | 1 |

Exit 2 is bad usage, no nish, a file that cannot be read, or a z3 failure
while checking the contract (`cannot be checked: z3 …`); see [Exit codes and
tool failures](exit-codes.md). `--format markdown` prints the result as a PR
comment and `--format json` as JSON.

The module under test runs in the test's own process and could print `pass`
lines itself. So `run` trusts only a transcript that ends with the line the
generated `main` prints after every clause has returned: `vector-done`, a
nonce fresh for this run (passed as the program's argument), and what each
clause returned. An early exit, a clause reported twice, a line after that
end, or a line that disagrees with its clause's return makes the run `ERROR`.
A module written to read the nonce from its own arguments could still forge a
run; [`spec mutate`](pr-gates.md#mutate) is the check against that, since a
gamed module's mutants all survive.

## What a pass means

`SATISFIED` is evidence, not proof. The implementation returns the spec's
printed vectors, and the contract's properties hold at every sample; nothing
was reasoned about the code itself. Where neither reaches, a bug passes: RFC
4231 prints no HMAC key between 64 and 128 bytes long, so an off-by-one in the
SHA-512 block-size test passes every RFC vector, and only a vector of the
contract's own at that length, or a property that pins the boundary, catches
it. Run [`spec mutate`](pr-gates.md#mutate) to list the plausible bugs a
contract cannot tell from the real code.
