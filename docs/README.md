# vector documentation

These docs are published as a site by [Scalar Docs](https://scalar.com/products/docs)
through its GitHub integration, from [`scalar.config.json`](../scalar.config.json)
at the repository root. There is no publish workflow: a push to `main` is the
release. [`docs.yml`](https://github.com/amritk/vector/blob/main/.github/workflows/docs.yml)
keeps the site honest on every push and pull request: the generated reference
must be current and every link must land.

| Directory | What it holds |
| --- | --- |
| [`guide/`](guide/index.md) | The user guide, written by hand: the landing page and getting started. |
| [`reference/`](reference/index.md) | The reference, generated: the command line, the file formats and the modules. |
| [`site/`](site/) | The site's look: the mark, the header logos and the theme. |

## Writing a guide page

A page under `docs/guide/` is written for people who use vector, and follows
these rules:

- **The reader runs vector, not its source.** Explain what a command does and
  how to use it; leave how it is built to the module reference.
- **The reference is normative.** A guide page states a flag, an exit code or
  a file format the way the generated reference does, and links it rather
  than repeating it. Where the two disagree, the guide is wrong.
- **A change a user sees updates its page in the same PR**: a command, a
  flag, an exit code, an install step or a message a page shows.
- **Every page has a route.** A new page gets a route in `scalar.config.json`;
  `node scripts/check-links.mjs` fails on a page under `docs/guide/` or
  `docs/reference/` that no route reaches, and on a route to a missing file.
  Only the `/reference` route is generated; every other route is written by
  hand.
- **Link pages relatively, everything else on GitHub.** The site serves only
  the files `scalar.config.json` routes. A relative link from a routed page to
  another opens it on the site, as it does on GitHub. A relative link to any
  other file (a source file, a fixture, a workflow) the site serves as a
  download, so a routed page links one as
  `https://github.com/amritk/vector/blob/main/<path>` (`tree/main/` for a
  directory). `node scripts/check-links.mjs` checks those URLs against the
  files here and refuses the relative form.
- **An anchor lands on both sites.** The site spells some heading IDs
  differently from GitHub: it drops `_`, keeps `.`, collapses and trims runs
  of `-`, and gives a heading below level 4 none. A link between routed pages
  to such a heading needs `<a id="<github-slug>"></a>` on its own line above
  it. `node scripts/check-links.mjs` names each anchor that needs one.

## The reference

Everything under `docs/reference/` is generated by
[`scripts/gen-reference.mjs`](https://github.com/amritk/vector/blob/main/scripts/gen-reference.mjs),
along with the `/reference` route in `scalar.config.json`. Never edit either
by hand: change the source and run `node scripts/gen-reference.mjs`.

- **The command line** is read from the declarations in `src/main.ts` and the
  `src/cli/*.ts` files it registers: one page per command, its arguments, its
  flags and the exit codes of `src/core/diag.ts`.
- **The formats** are the JSON Schemas in `schemas/*.json`, one page each.
- **The modules** are the exported declarations of `src/**/*.ts`, read by
  TypeDoc from their doc comments, one page per file.

The generator reads whatever `src/` holds; it has no list of modules or
commands to keep up. Each page starts with a "Do not edit by hand" comment
and depends on the source alone, byte for byte, so
`node scripts/gen-reference.mjs --check` can fail on a page that is stale,
missing or extra, and on a `/reference` route that no longer matches.

**The undocumented baseline only shrinks.** An exported declaration without
its doc comment, or a parameter without its `@param`, is a gap.
[`scripts/undocumented.txt`](https://github.com/amritk/vector/blob/main/scripts/undocumented.txt)
lists the gaps that are allowed, and `--check` fails both on a gap it does not
list and on a line that is no longer a gap. Document the declaration and
delete its line, or run `node scripts/gen-reference.mjs --update-baseline`,
which rewrites the file but refuses to add a line. `--grow-baseline` adds
lines too, and is only for a change to the rule itself.

## The site's look

[`site/`](site/) is the site's `assetsDir`. [`mark.svg`](site/mark.svg) is
the favicon and the source of `logo-light.svg` and `logo-dark.svg` (the mark
beside "vector", for the header); [`theme.css`](site/theme.css) holds the
colours of both modes. To see a change, run
`npx @scalar/cli project preview scalar.config.json` and look at the landing
page, a reference page and both colour modes.
